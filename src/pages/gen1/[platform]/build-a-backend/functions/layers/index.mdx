Lambdaレイヤーを使用すると、Lambda関数の共通コードとアセットを一元管理できます。Lambdaレイヤーを使用すると、以下のことができます。

1. _*コードとアセットを再利用*_: Lambda関数はこれらのレイヤーを活用して、関数全体で共有コードとアセットを再利用できます
2. _*関数のデプロイを高速化*_: Lambda関数を反復処理するのが大幅に高速になります。大量の静的コンテンツを含むレイヤーとは独立して更新できるためです

> **既知の制限**: レイヤーを使用する関数は、`amplify mock`を使用してローカルでモック化することはできません。開発環境を作成し、AWS Lambdaコンソール内で関数をテストすることをお勧めします。

![Lambdaレイヤーアーキテクチャ図](/images/layers-architecture.gif)

一般的なワークフローは以下のステップに分かれています。

1. Lambdaレイヤーを作成する
2. 共有コードとアセットをレイヤーに追加する
3. Lambdaレイヤーを関数に追加する
4. レイヤーと関数をデプロイする

## Lambdaレイヤーを作成する

レイヤーを作成するには、Amplifyプロジェクト内で以下のコマンドを実行します。

```bash
amplify add function
```

追加する機能として`Lambda layer`を選択します

```console
? Select which capability you want to add:
> Lambda layer (shared code & resource used across functions)
```

```console
? Provide a name for your Lambda layer: (layer-name)
? Choose the runtime that you want to use: (Use arrow keys)
❯ NodeJS
  Python
```

次に、**レイヤー名**を指定し、**サポートされているランタイム**を選択するワークフローが表示されます。現在、Amplify CLIはレイヤーに対してNodeJSまたはPythonランタイムサポートを提供しています。

```console
? The current AWS account will always have access to this layer.
  Optionally, configure who else can access this layer. (Hit <Enter> to skip)
◯ Specific AWS accounts
◯ Specific AWS organization
◯ Public (everyone on AWS can use this layer)
```

その後、**レイヤーのアクセス許可**を設定するよう求められます。

**現在のAWSアカウントは常にこのレイヤーにアクセスできます。**
さらに、以下の対象者のアクセスを設定できます。

- **特定のAWSアカウント**: アクセスを提供するAWSアカウントIDのコンマ区切りリストを指定します。
- **特定のAWS組織**: アクセスを提供するAWS組織IDのコンマ区切りリストを指定します。*AWS組織IDは`o-`で始まります。*
- **パブリック**: このレイヤーをすべてのAWSで利用可能にします。AWS内のすべてのユーザーがそのARNを使用してこのレイヤーを参照できます。
 
```console
Next steps:
Move your libraries to the following folder:
[NodeJS]: amplify/backend/function/<lambda-layer-name>/lib/nodejs

Include any files you want to share across runtimes in this folder:
amplify/backend/function/<lambda-layer-name>/opt

"amplify function update <function-name>" - configure a function with this Lambda layer
"amplify push" - builds all of your local backend resources and provisions them in the cloud
```

アクセス許可の設定後、Lambda レイヤーはすぐに使用できるようになります。

## 共有コードとアセットを追加する

レイヤーのセットアップが完了すると、`amplify/backend/function/`に`layer-name`が追加された新しいフォルダが表示されます。それぞれのランタイムのフォルダ構造は自動生成されます。

### 共有コードを追加する

<BlockSwitcher>

<Block name="NodeJS">

`nodejs`フォルダが自動生成されます。その中には、空の`package.json`ファイルと`node_modules`フォルダがあります。他のnode_modulesをオフロードする場合は、以下のいずれかを実行できます。

1. `nodejs`フォルダに`cd`して、依存関係を`package.json`ファイルに追加するか、
2. 既存の関数の`node_modules`コンテンツすべてをレイヤーの`node_modules`フォルダに移動する

レイヤーの`package.json`ファイル内に記載されている依存関係は、`amplify push`中にインストールおよびパッケージ化されます。

レイヤーの`node_modules`フォルダにあるノードモジュールは、関数の`node_modules`フォルダにノードモジュールがあるかのように、関数からアクセスできます。

*NodeJS関数用のLambdaレイヤーを活用するために、関数のコードを更新する必要すらありません。*

</Block>

<Block name="Python">

`python`フォルダが自動生成されます。その中には、空の`Pipfile`ファイルがあります。レイヤーの`Pipfile`ファイル内に記載されているパッケージは、`amplify push`中にインストールおよびパッケージ化されます。Python関数内から他のパッケージと同じように、これらのパッケージを`import`できます。

</Block>

</BlockSwitcher>

### 共有アセットを追加する

大きな画像や他のファイルなど、さまざまな関数で共有したいアセットは、`amplify/backend/function/<layer-name>/opt/`フォルダに配置できます。関数のコードは、`/opt/`パスでファイルを検索することで、任意のアセットをインポートできます。

### Lambdaレイヤーのバージョン

`amplify push`または`amplify update function`を実行するたびに、Amplify CLIはレイヤーのコンテンツが変更されているかどうかをチェックし、自動的に新しい*レイヤーバージョン*を作成します。レイヤーのバージョンは不変であり、関数は常に特定のレイヤーバージョンを使用します。

大量のnode_modulesが存在する場合のデプロイを高速化するために、Amplify CLIは各モジュールの`package.json`ファイル内の変更のみをスキャンします。Amplify CLIが最新の変更を検出していない場合は、ノードモジュールの`package.json`コンテンツの少なくとも1つが変更されていることを確認してください。

## レイヤーを関数に追加する

`amplify add function`を実行して新しい関数を作成し、Lambdaレイヤーを追加するか、`amplify update function`を使用して既存の関数にレイヤーを追加できます。プロンプトが表示されたときに`Lambda function`を選択すると、ガイド付きフロー中に次の質問が表示されます。

```console
...
? Do you want to enable Lambda layers for this function? Yes
? Provide existing layers or select layers in this project to access from this function (pick up to 5):
 ◯ Provide existing Lambda layer ARNs
❯◉ myamplifylayer1
 ◯ myamplifylayer2
```

AWSの既存レイヤーをそのARNで参照するか、Amplifyプロジェクトのリストされたレイヤーを選択できます。

```console
? Select a version for myamplifylayer1:
❯ Always choose latest version
  2: Updated layer version 2021-06-08T05:33:42.651Z
  1: Updated layer version 2021-06-08T05:30:43.101Z
```

Amplifyプロジェクトからレイヤーを追加する場合、特定のレイヤーバージョンを選択するか、常に最新のレイヤーバージョンを選択することもできます。最大のレイヤーバージョン番号は最新の変更を表しています。

```console
? Modify the layer order:
(Layers with conflicting files will overwrite contents of layers earlier in the list):
- layer2
- layer3
- layer6
- <ARN1>
- <ARN2>
```

レイヤーはコンテンツが重複する可能性があるため、レイヤーの順序が重要です。必要に応じて、次のステップでレイヤーの順序を調整できます。

これで、関数にレイヤーが正常に追加されました。

## Lambdaレイヤーを使用したLambdaレイヤーと関数のデプロイ

レイヤーと関数での変更の準備ができたら、`amplify push`を実行してデプロイできます。

レイヤーのコンテンツが更新され、関連する権限がある場合、Amplify CLIは、これらの権限を新しいバージョンに引き継ぐかどうかを尋ねるプロンプトを表示します。

```console
Content changes in Lambda layers detected.
Suggested configuration for new layer versions:

myamplifylayer1
  - Description: Updated layer version  2021-06-08T05:33:42.651Z

? Accept the suggested layer version configurations? (Y/n)
```

`amplify push`中に、レイヤーバージョンの説明を変更できます。デフォルトでは、Amplify CLIは説明を`Updated layer version <timestamp>`として設定します。

## レイヤーコンテンツを更新する

レイヤーフォルダ内のファイル変更は、Amplify CLIによって自動的に追跡されます。変更がある場合、Amplify CLIは変更を含む新しいレイヤーバージョンを作成します。

## レイヤー設定を更新する

`amplify update function`を実行し、`Lambda layer`を選択することで、レイヤーの権限を更新できます。

次に、設定を更新するレイヤーを選択するよう求められます。

#### 注: レイヤーアクセス許可をパブリックから特定に更新する
  - Lambdaレイヤーをパブリックアクセスから特定（アカウント/組織）アクセスに更新するには、「amplify update」CLIフロー内で特定のAWSアカウント/組織を選択する前に、パブリックアクセスを**選択解除**して削除することを忘れないでください。
  - すでに「パブリック」アクセスを選択している場合、追加の「特定の」AWSアカウント/組織を追加するだけでは、Lambda レイヤー設定に影響を与えません。パブリックアクセスは自動的に削除されません。

## レイヤーを削除する

Lambdaレイヤーを削除するには、`amplify function remove`コマンドを実行し、`Lambda layers`を選択します。次に、削除するレイヤーを選択するよう求められます。特定のレイヤーバージョンをすべて削除することができます。

> 警告: レイヤーを削除すると、そのレイヤーを使用するように関数を設定することはできなくなります。ただし、既にレイヤーを使用している関数は、そのレイヤーへのアクセスを継続できます。

```console
? Choose the resource you would want to remove <lambda-layer-name> (layer)
When you delete a layer version, you can no longer configure functions to use it.
However, any function that already uses the layer version continues to have access to it.
? Choose the Layer versions you want to remove.
❯◯ 1: Updated layer version 2021-06-08T05:30:43.101Z
 ◯ 2: Updated layer version 2021-06-08T05:33:42.651Z
? Are you sure you want to delete the resource? This action deletes all files related to this resource from the backend directory. (Y/n)
```
